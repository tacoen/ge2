Kick-start a ge app

PHP or static HTML, CSS in @layers, JS as ES modules. No build step — files are served as they are.

open the demo function reference

1 · Start a project

Make a sibling folder next to ge2/ and copy the starter files into it. boiler.html is the empty page; it becomes your index.html (or rename it index.php).

cd /var/www/dash
mkdir -p myapp/css myapp/js
cp ge2/boiler.html                 myapp/index.html
cp ge2/style.css ge2/script.js     myapp/
cp ge2/boiler-vars-overrides.css   myapp/css/vars-overrides.css
cp -r ge2/css/ge2                  myapp/css/
cp -r ge2/js/ge2                   myapp/js/
cp ge2/boiler-config.js            myapp/js/ge2/config.js   # no plugins enabled
cp ge2/favicon.ico                 myapp/
cp ge2/boiler-CLAUDE.md            myapp/CLAUDE.md          # rules for AI assistants

The boiler-* files are clean starters. boiler-config.js replaces ge's own config.js, which enables the text-editor plugin for the demo — yours starts with an empty plugin list, and the sync never overwrites it. boiler-vars-overrides.css is an empty override sheet, so you start from the stock palette rather than ge's.

That is a working page: theme applied before first paint, icons hydrated, tabs and accordions wired — all from script.js.

2 · Keep ge in sync

css/ge2/ and js/ge2/ in your app are a vendored copy — never edit them. Pull upstream changes with:

../sync-ge2.sh -n   # dry run
../sync-ge2.sh

The sync mirrors upstream with --delete but leaves config.js and icons-list.js alone — those two are yours. To keep any other file, list it in myapp/.ge2-sync-exclude.

Need a framework change? Write myapp/ge2-suggestions/YYYY-MM-DD-topic.md (what, why, diff) and it gets reviewed and applied upstream here.

3 · Configure

js/ge2/config.js is the one framework file meant to be edited per project:

export const config = {
  theme: 'auto',                 // 'auto' | 'light' | 'dark'
  themeStorageKey: 'myapp-theme', // unique per app on a shared origin
  plugins: { /* see step 7 */ },
};

Colours and type: tune them on the Theme page, then download the result as css/vars-overrides.css. Icons: edit the set on the icons page and export js/ge2/icons-list.js.

4 · Write CSS

style.css is the single wiring point. It declares the layer order before the imports — keep it that way:

@layer units, base, ui, plugin, page, utils;

App-wide rules go in its @layer page { } block, app-wide utilities in @layer utils { }. Use tokens only — var(--token); check css/ge2/vars.css before inventing one.

5 · Write JS

ES modules only — no inline <script>, no onclick=. Start from script.js:

import { ui } from './js/ge2/ui.js';
import { icx } from './js/ge2/icons.js';

icx.observe();
ui.tabs();
ui.accordion();
// opt-in: ui.handleForm(form, fn) · ui.modal('open', id) · ui.onKey(...)

localStorage only through js/ge2/store.js — raw access throws in a private window.

6 · Add a module

A module <name> is one CSS entry and one JS entry, each with an optional folder beside it:

PathHolds
<name>/index.htmlentry page + subpages; PHP in <name>/php/
css/<name>.css@import url('../style.css'); then @layer page { … }
css/<name>/extra sheets, only when one is not enough
js/<name>.jsJS entry
js/<name>/submodules imported by the entry

A module sheet never re-imports ge and never redeclares the layer order — style.css already did both.

7 · Add a plugin

Copy the folder in, then add one key to config.plugins:

cp -r ge2/ge2-plugins/text-editor myapp/ge2-plugins/

// js/ge2/config.js
plugins: { 'text-editor': {} },

// script.js
import { loadPlugins } from './js/ge2/plugins.js';
await loadPlugins();

Its CSS lands in layer plugin, between ui and page. Comment the key out and nothing is fetched. Each plugin's readme.md covers its settings.

House rules

  • Paths always relative — no hardcoded host or domain.
  • CDN deps are fine: pin the version, keep the URL in js/ge2/config.js.
  • Server code goes in php/ (root) or <name>/php/. No endpoint authenticates — gate them yourself.
  • Framework and app code never mix.
