theme · colour · light

The colour editor. --ac, --bg, --fg (Main) and the five component seeds (Swatch) start at the stylesheet's values for the current theme. Any edit is a real override, set on <html>: the whole page follows it, it is kept per theme (switching swaps it in), it applies on every demo page, and buckets save it. Clearing a field, typing the stylesheet's own value, or clicking the swatch drops the override; reset colours drops them all, in both themes. theme · buckets below shows what is changed, as the vars-overrides.css an app drops in after vars.css. Under Derived, the scale steps --ac toward --bg (bg1…bg5: 15, 30, 45, 60, 85%), toward --fg (fg1…fg5) and toward transparent (tr1…tr4), each labelled with what it is for. The demo beside it — an app dashboard, a webpage and a docs article, one per tab — is painted from those steps; its chips and callouts take the seeds. CSS, folded under the panel, lists the formulas in force. Every field takes any CSS colour.

Docs / Sharing / Share a folder

Share a folder

Give someone access to a folder with a link, or invite them by email so they can edit with you.

Create a link

Select the folder, press Ctrl + L, and copy the link. Anyone with the link can view; to let them edit, turn on edit rights. From the command line, use files share:

files share ~/Projects/ge2 --expires 7d
# https://files.example/s/4kq9 (view, expires in 7 days)
Note

Links to a folder include everything added to it later.

Link options

OptionDefaultWhat it does
--expiresneverTurns the link off after a time, e.g. 7d
--editoffLets people with the link change files
--passwordnoneAsks for a password before opening
Before you share

Edit rights let people delete files. Deleted files stay in Trash for 30 days.

Sharing a folder never moves it. It stays in your Files, and you can revoke access at any time.

theme · typography

    
Font, size, weight and colour for body text, h1–h6, small, pre and blockquote. Each element reads its own tokens — --body-font, --h1-weight, --small-color… — declared in vars.css and applied in base.css. Every option is another token, written as var(--token); the option marked * drops the override and shows what the stylesheet gives. A * inherit means the token is left at initial, so the element takes its parent's value. Heading sizes are the existing --h1…--h6. Changes persist, go into buckets, and are written to the :root block of download vars-overrides.css.

    

    

      
    

  


  

    
theme · buckets

    
Every change on this page — colours, type and typography — is kept in localStorage and applied on every demo page, so a reload restores it. A bucket is a named snapshot of both themes — save, load, delete. The block below shows the overrides as CSS, live. download vars-overrides.css saves that block as the app's css/vars-overrides.css — changed values only; style.css imports it right after vars.css, so it wins. Light and dark are both written, each scoped to its own [data-theme] block so neither leaks into the other.
